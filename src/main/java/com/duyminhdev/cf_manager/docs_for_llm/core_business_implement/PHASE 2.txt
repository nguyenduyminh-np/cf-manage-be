Bắt đầu **PHASE 2**: mình sẽ đưa **full DTO code** theo đúng 3 rule bạn chốt:

* bám kiến trúc `dto/base`, `dto/request`, `dto/response`, `dto/db_result/native_sql`
* validation nằm ở `request DTO`
* về sau controller/service/search sẽ bám đúng pattern **JPA Criteria** và **Native Query** từ 3 tài liệu bạn gửi.   

Mình giữ convention:

* tất cả class đều suffix `DTO`
* các API đều dùng `POST`
* search/list có phân trang sẽ `extends PageFilterRequest`
* response không có validation
* `db_result/native_sql` chỉ để map raw query result, không trả thẳng ra API.

# E. 3 lưu ý quan trọng trước khi sang Phase 3

### 1. `PageFilterRequest` hiện tại chưa có annotation validation

Trong tài liệu JPA Criteria, phần page/sort boundary được kiểm rất chặt. Ở Phase 3 mình sẽ cần:

* hoặc patch `PageFilterRequest`
* hoặc validate/sanitize ở service/repository helper
  Tốt nhất là patch DTO base sau nếu bạn cho phép. 

### 2. `sortField` cho search DTO chưa whitelist tại DTO

Theo tài liệu, whitelist sort field phải kiểm ở repository/spec/native layer, không chỉ regex ở DTO. Phase 3 mình sẽ làm phần đó trong:

* `TableBookingSpec`
* `DishSpec`
* native repository `mapSortFieldToDbColumn(...)`

### 3. Native result DTO phải map bằng alias tuyệt đối

Phase 3 khi viết native repository, các alias SQL phải khớp 100% với field names trong `db_result/native_sql`, nếu không map tuple sẽ lỗi.
