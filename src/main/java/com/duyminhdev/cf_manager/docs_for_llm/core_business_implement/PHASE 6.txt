# 6.10. Giai thich chi tiet cac mismatch can xu ly truoc khi implement

## 6.10.1. DTO package mismatch (quan trong nhat)

- Ban draft cu dung `com.duyminhdev.cf_manager.dto.crud.request.*` va `dto.crud.response.*`.
- Codebase hien tai dang dung `com.duyminhdev.cf_manager.dto.request.*` va `dto.response.*`.
- Neu copy draft cu vao controller that se loi compile ngay (cannot resolve symbol package).
- Ban plan nay da doi import ve dung package hien tai de khi implement tranh sai ngay tu dau.

## 6.10.2. Mismatch trang thai thuc thi

- Tai thoi diem hien tai project moi co `AuthController`, cac controller phase 6 chua tao.
- Vi vay, phase 6 hien la plan, chua co endpoint runtime cho table/booking/order/payment.

## 6.10.3. Quy uoc input da chot

- Nguyen tac tong quat: cac API mutate (create/update/update-status/confirm-payment/detail/search co filter) dung `@Valid @RequestBody`.
- Ngoai le da chot de giu tinh linh hoat: `dish/list`, `dish-category/list`, `payment-method/list`, `invoice/count` duoc phep `@RequestBody(required = false)`.
- Neu request body null, controller tao `safeRequest = new XxxRequestDTO()` va goi service voi gia tri mac dinh.
- API docs can ghi ro 2 nhom endpoint tren de FE khong hieu sai contract.

## 6.10.4. Mismatch xu ly validation error

- Neu dung `@Valid`, can bo sung `MethodArgumentNotValidException` handler trong `GlobalExceptionHandler`.
- Neu khong bo sung, loi validation van bi bat, nhung format thong diep se khong dong bo voi khung `ErrorResponse` mong muon.

# 6.11. Exception handler plan + HTTP status mapping (theo format project hien tai)

## 6.11.1. Format response loi chuan cua project

Format can giu dung theo `ErrorResponse` hien tai:

```json
{
  "timestamp": "2026-03-31T10:15:30+07:00",
  "status": 400,
  "error": "Bad Request",
  "code": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "details": {
    "fieldA": "must not be blank"
  },
  "path": "/api/v1/table/search"
}
```

## 6.11.2. Ma tran exception -> HTTP status

1. `MethodArgumentNotValidException` -> `400 Bad Request`
2. `InvalidDataException` -> `400 Bad Request`
3. `DuplicatedUsernameException` -> `409 Conflict`
4. `AuthenticationException` (qua `CustomAuthenticationEntryPoint`) -> `401 Unauthorized`
5. `AccessDeniedException` (qua `CustomAccessDeniedHandler`) -> `403 Forbidden`
6. `Exception` fallback -> `500 Internal Server Error`

## 6.11.3. Error code de xai nhat quan

1. `VALIDATION_ERROR`
2. `INVALID_DATA`
3. `DUPLICATED_USERNAME`
4. `AUTH_UNAUTHORIZED`
5. `ACCESS_DENIED`
6. `INTERNAL_SERVER_ERROR`

## 6.11.4. Ke hoach patch handler (plan, chua implement)

1. Them `@ExceptionHandler(MethodArgumentNotValidException.class)` vao `GlobalExceptionHandler`.
2. Trich field errors vao `details` dang map `field -> message`.
3. Giu nguyen format `build(...)` de khong vo JSON contract hien tai.
4. Khong doi logic cua `CustomAuthenticationEntryPoint` va `CustomAccessDeniedHandler`, chi verify code/status/message map dung ma tran tren.
