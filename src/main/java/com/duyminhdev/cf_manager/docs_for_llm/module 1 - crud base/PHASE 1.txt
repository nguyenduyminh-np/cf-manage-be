PHASE 1:
4 nguyên tắc đã chốt:

* project đang ở **Spring Boot 3.5.12 + Java 21** nên Phase 1 không cần đổi `pom.xml` nền. 
* response vẫn phải bọc bằng `ApiResponse<T>` / `PageResponse<T>` theo `dto/base` đang có.
* DTO phải tách `crud/request`, `crud/response`, `db_result/native_sql`, không dùng chung request và response.

Trong tin này, mình đưa **Phase 1 full code**:
**entity patch + enums + constants + utility nền**.
Đây là phase phải làm trước để các phase repository / DTO / service phía sau cắm vào được.

## 1.1. Patch `TableEntity.java`

Bạn đã chốt thêm `floor`, `seat`, `slot`. Flow cũ cũng cần lọc bàn theo tầng, số người, trạng thái bàn.

**File:** `src/main/java/com/duyminhdev/cf_manager/entity/TableEntity.java`

```java
package com.duyminhdev.cf_manager.entity;

import jakarta.persistence.*;
import lombok.*;

import java.time.LocalDateTime;

@Entity
@Table(name = "dining_table")
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class TableEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id")
    private Integer id;

    @Column(name = "table_code", length = 255)
    private String tableCode;

    @Column(name = "table_name", nullable = false, length = 255)
    private String tableName;

    /**
     * Lưu code trạng thái bàn trong DB.
     * Ví dụ: AVAILABLE / BOOKED / OCCUPIED
     */
    @Column(name = "table_status", nullable = false, length = 255)
    private String tableStatus;

    @Column(name = "floor")
    private Integer floor;

    /**
     * Sức chứa bàn, user đã chốt DB đã có và hiện giá trị là 4.
     */
    @Column(name = "seat")
    private Integer seat;

    /**
     * Slot hiển thị / thứ tự / phân vùng bàn theo DB mới.
     */
    @Column(name = "slot")
    private Integer slot;

    @Column(name = "created_at", nullable = false)
    private LocalDateTime createdTime;

    @Column(name = "is_active", nullable = false)
    private Boolean active;
}
```

### Ghi chú triển khai

* `tableStatus` vẫn để `String` ở entity để bám DB hiện tại.
* Enum sẽ map ở service/mapper, không ép entity đổi sang `@Enumerated` ngay từ đầu để tránh phát sinh mismatch DB không cần thiết.
* `seat` và `slot` để kiểu `Integer` cho an toàn nullability khi dữ liệu cũ chưa backfill đủ.

Flow booking cũ có `note`, `bookingTime`, `customerName`, `phoneNumber`, `deposit`, `bookingStatus`.

Bạn chưa paste entity `TableBooking` trong log đầu, nhưng theo plan thì file này cần patch thêm `note`.

**File:** `src/main/java/com/duyminhdev/cf_manager/entity/TableBooking.java`

```java
package com.duyminhdev.cf_manager.entity;

import jakarta.persistence.*;
import lombok.*;

import java.math.BigDecimal;
import java.time.LocalDateTime;

@Entity
@Table(name = "table_booking")
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class TableBooking {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id")
    private Integer id;

    @Column(name = "expected_arrive_time", nullable = false)
    private LocalDateTime bookingTime;

    @Column(name = "check_in_at")
    private LocalDateTime checkInTime;

    /**
     * Lưu code trạng thái booking trong DB.
     * Ví dụ: PENDING_CONFIRMATION / CONFIRMED / CANCELLED / COMPLETED
     */
    @Column(name = "booking_status", nullable = false, length = 255)
    private String bookingStatus;

    @Column(name = "deposit_amount", precision = 18, scale = 0)
    private BigDecimal deposit;

    @Column(name = "customer_name", length = 255)
    private String customerName;

    @Column(name = "phone_number", length = 50)
    private String phoneNumber;

    @Column(name = "note", length = 255)
    private String note;

    @Column(name = "created_at", nullable = false)
    private LocalDateTime createdTime;

    @Builder.Default
    @Column(name = "is_active", nullable = false, columnDefinition = "tinyint(1) DEFAULT 1")
    private Boolean active = true;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "account_id", nullable = false, foreignKey = @ForeignKey(name = "fk_table_booking_account_id"))
    private Account account;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "dining_table_id", nullable = false, foreignKey = @ForeignKey(name = "fk_table_booking_dining_table_id"))
    private TableEntity table;
}
```

### Ghi chú

* Nếu entity hiện tại của bạn đã có hầu hết field này, chỉ cần thêm riêng `note`.
* Tên cột đang bám đúng logic từ tài liệu cũ.

## 1.3.1. `TableStatusEnum.java`

**File:** `src/main/java/com/duyminhdev/cf_manager/enums/TableStatusEnum.java`

```java
package com.duyminhdev.cf_manager.enums;

import lombok.Getter;

import java.util.Arrays;

@Getter
public enum TableStatusEnum {

    AVAILABLE("AVAILABLE", "Bàn trống"),
    BOOKED("BOOKED", "Đã đặt"),
    OCCUPIED("OCCUPIED", "Đang sử dụng");

    private final String code;
    private final String displayName;

    TableStatusEnum(String code, String displayName) {
        this.code = code;
        this.displayName = displayName;
    }

    public static TableStatusEnum fromCode(String code) {
        return Arrays.stream(values())
                .filter(item -> item.code.equalsIgnoreCase(code))
                .findFirst()
                .orElseThrow(() -> new IllegalArgumentException("Invalid table status code: " + code));
    }

    public static boolean isValidCode(String code) {
        return Arrays.stream(values())
                .anyMatch(item -> item.code.equalsIgnoreCase(code));
    }
}
```

public final class ValidateValueConstants {

### `EnumUtils.java`

**File:** `src/main/java/com/duyminhdev/cf_manager/utils/EnumUtils.java`

```java
package com.duyminhdev.cf_manager.utils;

import java.util.Arrays;

public final class EnumUtils {

    private EnumUtils() {
    }

    public static <E extends Enum<E> & EnumCodeSupport> E fromCode(Class<E> enumClass, String code) {
        return Arrays.stream(enumClass.getEnumConstants())
                .filter(item -> item.getCode().equalsIgnoreCase(code))
                .findFirst()
                .orElseThrow(() -> new IllegalArgumentException(
                        "Invalid code '" + code + "' for enum " + enumClass.getSimpleName()
                ));
    }

    public static <E extends Enum<E> & EnumCodeSupport> boolean isValidCode(Class<E> enumClass, String code) {
        return Arrays.stream(enumClass.getEnumConstants())
                .anyMatch(item -> item.getCode().equalsIgnoreCase(code));
    }
}
```

## 1.7. Tạo utility lấy user hiện tại từ JWT context

Base security hiện tại đã set `Authentication` vào `SecurityContext` khi JWT hợp lệ, nên phase service về sau có thể resolve username/account từ context thay vì tin vào `accountId` request. 

**File:** `src/main/java/com/duyminhdev/cf_manager/utils/SecurityUtils.java`

```java
package com.duyminhdev.cf_manager.utils;

import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;

public final class SecurityUtils {

    private SecurityUtils() {
    }

    public static String getCurrentUsername() {
        Authentication authentication = SecurityContextHolder.getContext().getAuthentication();

        if (authentication == null || authentication.getName() == null) {
            throw new IllegalStateException("Cannot resolve current authenticated username");
        }

        return authentication.getName();
    }

    public static boolean isAuthenticated() {
        Authentication authentication = SecurityContextHolder.getContext().getAuthentication();
        return authentication != null
                && authentication.isAuthenticated()
                && authentication.getName() != null
                && !"anonymousUser".equalsIgnoreCase(authentication.getName());
    }
}
```

## 1.8. Tạo utility paging nền cho DTO base hiện có

Project hiện có `PageFilterRequest` với `page`, `limit`, `sortField`, `sortDir`, và `PageResponse<T>` với `pageNo`, `pageSize`, `totalElements`, `totalPages`. Ta nên normalize ngay từ Phase 1 để các phase search không lặp sanitize. 

**File:** `src/main/java/com/duyminhdev/cf_manager/utils/PageUtils.java`

```java
package com.duyminhdev.cf_manager.utils;

public final class PageUtils {

    private static final int DEFAULT_PAGE = 0;
    private static final int DEFAULT_LIMIT = 20;
    private static final int MAX_LIMIT = 100;

    private PageUtils() {
    }

    public static int normalizePage(Integer page) {
        if (page == null || page < 0) {
            return DEFAULT_PAGE;
        }
        return page;
    }

    public static int normalizeLimit(Integer limit) {
        if (limit == null || limit < 1) {
            return DEFAULT_LIMIT;
        }
        return Math.min(limit, MAX_LIMIT);
    }

    public static int calculateTotalPages(long totalElements, int pageSize) {
        if (pageSize <= 0) {
            return 0;
        }
        return (int) Math.ceil((double) totalElements / pageSize);
    }
}
```

# Vì sao Phase 1 này đúng với 3 tài liệu bạn gửi

DTO architecture yêu cầu tách trách nhiệm rõ, validation phải nằm ở request DTO, response phải bọc bằng base wrapper, và data-access DTO phải tách khỏi API DTO. Phase 1 mình mới dựng **nền** để phase 2 làm DTO đúng chuẩn đó, không nhét logic lung tung từ sớm. 

JPA Criteria document yêu cầu paging/sort/search phải có boundary validation, whitelist sort field và xây predicate an toàn. Vì vậy mình đã đặt sẵn `ValidateValueConstants` và `PageUtils` để phase sau dựng `crud/request/*SearchRequestDTO` đúng pattern. 

Native Query document yêu cầu named parameters, whitelist sort mapping, tuple alias mapping sang result DTO trung gian. Vì vậy mình chưa ép DTO response ngay ở phase này, mà để chừa chỗ cho `dto/db_result/native_sql/*` ở Phase 2-3.
