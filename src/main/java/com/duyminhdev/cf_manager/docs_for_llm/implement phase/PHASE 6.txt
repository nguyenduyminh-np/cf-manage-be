Bắt đầu **PHASE 6 — Controller layer**.

Phase này mình khóa theo 4 nguyên tắc đã chốt:

* **Tất cả API dùng POST**
* **Controller chỉ nhận `@Valid @RequestBody`**
* **Trả về `ApiResponse<T>` hoặc `ApiResponse<PageResponse<T>>`**
* **Không viết business logic trong controller**, toàn bộ nghiệp vụ đã nằm ở service phase 5.
  Điều này bám đúng tài liệu DTO architecture và flow service cũ của module TableList.

Ngoài ra, màn hình cũ dùng 16 API cho 4 flow chính: hiển thị bàn, đặt bàn, gọi món, thanh toán. Phase 6 dưới đây map đúng các flow đó nhưng theo convention mới: **POST-only + DTO contract mới**.

# 6.10. Patch rất nên làm ngay: validation handler

Hiện `GlobalExceptionHandler` mới có `InvalidDataException`, `DuplicatedUsernameException`, `Exception`, nhưng **chưa có** handler cho `MethodArgumentNotValidException`. Trong khi phase 6 controller đang dùng `@Valid @RequestBody` khá nhiều. Base project hiện đã có `GlobalExceptionHandler`, nên nên patch luôn để validation message trả đẹp. 

## 6.10.1. Patch `GlobalExceptionHandler.java`

```java id="4szl5b"
package com.duyminhdev.cf_manager.exceptions;

import com.duyminhdev.cf_manager.dto.base.ErrorResponse;
import jakarta.servlet.http.HttpServletRequest;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.time.OffsetDateTime;
import java.util.LinkedHashMap;
import java.util.Map;

@RestControllerAdvice
public class GlobalExceptionHandler {

    private ResponseEntity<ErrorResponse> build(
            HttpStatus status,
            String code,
            String message,
            Object details,
            HttpServletRequest req) {
        return ResponseEntity.status(status).body(
                ErrorResponse.builder()
                        .timestamp(OffsetDateTime.now())
                        .status(status.value())
                        .error(status.getReasonPhrase())
                        .code(code)
                        .message(message)
                        .details(details)
                        .path(req.getRequestURI())
                        .build());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleMethodArgumentNotValid(
            MethodArgumentNotValidException ex,
            HttpServletRequest req) {

        Map<String, String> fieldErrors = new LinkedHashMap<>();
        for (FieldError fieldError : ex.getBindingResult().getFieldErrors()) {
            fieldErrors.putIfAbsent(fieldError.getField(), fieldError.getDefaultMessage());
        }

        return build(
                HttpStatus.BAD_REQUEST,
                "VALIDATION_ERROR",
                "Request validation failed",
                fieldErrors,
                req
        );
    }

    @ExceptionHandler(InvalidDataException.class)
    public ResponseEntity<ErrorResponse> invalidData(
            InvalidDataException ex,
            HttpServletRequest req) {
        return build(HttpStatus.BAD_REQUEST,
                "INVALID_DATA",
                ex.getMessage(),
                null,
                req);
    }

    @ExceptionHandler(DuplicatedUsernameException.class)
    public ResponseEntity<ErrorResponse> duplicatedUsername(
            DuplicatedUsernameException ex,
            HttpServletRequest req) {
        return build(HttpStatus.CONFLICT,
                "DUPLICATED_USERNAME",
                ex.getMessage(),
                null,
                req);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGenericException(
            Exception ex,
            HttpServletRequest req) {
        ex.printStackTrace();
        return build(HttpStatus.INTERNAL_SERVER_ERROR,
                "INTERNAL_SERVER_ERROR",
                "An unexpected error occurred",
                ex.getMessage(),
                req);
    }
}
```

# 6.11. 3 lưu ý rất quan trọng sau Phase 6

## 1. Các API `list`/`count` đang cho phép body null

Mình cố tình để:

* `DishListRequestDTO`
* `DishCategoryListRequestDTO`
* `PaymentMethodListRequestDTO`
* `InvoiceCountRequestDTO`
  có thể nhận `null body`, rồi controller tự tạo request mặc định. Điều này giúp frontend gọi nhẹ hơn.

## 2. Security hiện tại không cần sửa route whitelist

Các controller mới không cần whitelist, vì nghiệp vụ table/booking/order/payment đều phải qua JWT. `SecurityConfig` hiện đang để mọi route ngoài `/api/v1/auth/**` đều authenticated, phù hợp với bài toán này. 

## 3. Controller chỉ orchestration, không chứa business

Điều này bám đúng tài liệu DTO architecture và service explain cũ:

* validation rìa ở request DTO
* orchestration ở controller
* nghiệp vụ ở service
* data access ở repository/spec/native repository.
